# 选择题改造与三方案对照 v1.0

> 把主轮 92 题 + 干预轮 92 题改造成**五选一**，判分 `pick == answer`（**零判官**）。
> 在此题库上跑三个方案：直喂全文 / 千问向量 RAG / 灵枢多路召回。
> **本页所有读数都可复现**——判分不经过任何 LLM。

---

## 一、为什么改选择题

原榜判分是「规则层 + 语义判官」，判官对每条采分点判 `strict/paraphrase/miss`。

问题：**判官把两件事混在一个分里**——「记忆对不对」和「话说得干不干净」。

我们在 8 个失败样本上看到：**4 题 required 完全满足，只因多说了一句无据细节被判 fail**
（例如「回屋瘫着」四个字被判「违反禁止」+「未知当事实」）。

**改成选择题后**：

| 项 | 原方案 | 选择题 |
|---|---|---|
| 判分 | 判分器 + 语义判官 | **`pick == answer`** |
| 判官差异 | ≈1.8pp（换执行者）| **0** |
| 复现性 | 依赖判官 | **逐字节可复现** |

**代价**：只测「认出」，不测「自由复述」（我们实测两者差 60+ 点）。**两轨应并存**。

## 二、题目怎么造

### 1. 五选项结构

| 项 | 内容 | 对应原 rubric |
|---|---|---|
| **A** | 满足全部 `required`、不编造、不多说 | 正确 |
| **B** | 漏掉一条关键要点 | `required` 不全 |
| **C** | 编造原文没有的细节 | 版规外内容 |
| **D** | 与某条要点相反 / 归错主体 | 与 fact 冲突 |
| **E** | 「我不确定，现有记录里没有足够信息回答这个」| 资料不足 |

### 2. 答案键来源

| 题族 | 数量 | 来源 |
|---|---:|---|
| 主轮 o（开放） | 54 | `cards/oXXX.yaml`（**作者裁定台账**）|
| 主轮 q（客观） | 38 | `cards/qXXX.yaml`（**作者裁定台账**）|
| **干预轮 i（反事实）** | **90** | **机器从 base 卡推导**（原答案键不公开）|

**干预轮的 rubric 生成方式**：给定 base 题要点 + 反事实假设，生成三类要点：
1. 不依赖被抽掉内容的要点（仍成立）；
2. 依赖被抽掉内容的要点（明确指出失去依据）；
3. 断点在哪一环。

**这批 rubric 是机器生成的，不是作者裁定**——引用时必须带这个限定。

### 3. 三轮人工复核（修 18 题、剔 2 题）

| 问题类型 | 例子 | 修法 |
|---|---|---|
| **答案依赖语料外信息** | 选项引用「作者 2026-09-30 裁定」「接口 q037」——全文 6 万字里这些词出现 **0 次** | 删除或改答案=E |
| **长短版干扰项** | B 是 A 删掉末尾一段（前 169 字完全相同）| 重写成「平行但错一条」 |
| **双解** | A、C 都合理，只是详略不同 | 让干扰项有**可指出的具体事实错误** |
| **万能防御句** | 「材料里没有给出判断依据，此处不下结论」——任何选项都能自圆其说 | 删除，改成明确断言 |
| **归属错误** | 把《风之种》错认成「派蒙的包装装置」——原文是**陈默创作的反制寓言** | 按原文重写 |
| **剔除** | q016i、o053i：改后已不是反事实题 | 从题库移除 |

**终版 182 题**（open 54 / objective 38 / intervention 90）。

## 三、判分器

`grade_mcq.py`（本仓根目录），六项功能：

| # | 功能 |
|---:|---|
| 1 | 计分 `pick == answer`（零噪声）|
| 2 | 分组：有答案 / 资料不足 |
| 3 | 错误分类：乱说 / 过度谨慎 / 选错实质项 / 弃答 |
| 4 | **二项检验**（对 1/选项数 基线）|
| 5 | 混淆矩阵 + 缺答/多答/非法字母校验 |
| 6 | 原榜口径三张表（人物 / 考点 / 间隔）|

|---|---:|---|

| 全对 | 100% | p=0.00 ✅ |
| 随机 | 21.7% | p=0.305 ✅ |

## 四、三方案对照（同一 182 题、同一作业模型 DeepSeek-flash）

| 方案 | 整体 | open(54) | objective(38) | intervention(90) | 平均材料 |
|---|---:|---:|---:|---:|---:|
| **直喂全文** | **98.9%** | 98.1% | 97.4% | **100%** | 60,000 字 |
| **千问 RAG**（qwen3-embedding-4b, top-8）| **84.1%** | 70.4% | 78.9% | 94.4% | 6,640 字 |
| **灵枢**（多路召回, k=8）| **76.9%** | 59.3% | 65.8% | 92.2% | 7,515 字 |
| （随机基线）| 20% | | | | |

### 三个可读的结论

**① 6 万字语料上，直喂 ≫ 检索（98.9% vs 84.1% vs 76.9%）。**

直喂每题 6 万字（约 3.6 万 token），182 题约 10 元——**在这个规模上便宜且最强**。

**② 检索方案里，材料更少反而更好。**

| 方案 | 材料 | 效果 |
|---|---:|---:|
| 灵枢 | 7,515 字 | 76.9% |
| 千问 | **6,640 字** | **84.1%** |

**灵枢多给 13% 材料却低 7.2 点 → 问题在检索精度，不在材料量。**

**③ 干预题（反事实）两者都高（92–94%）。**

因为干预题的答案结构是「仍成立 / 失去依据 / 断点」——**看到部分材料就能推**，不需要完整事实。

## 六、边界（诚实清单）

1. **干预轮 90 题的 rubric 是机器推导**，非作者裁定；
2. 三轮复核是逐题人工裁定，但**出题/质检环节仍由 LLM 完成**（GLM-5.3-flash / DeepSeek-flash），可能带模型偏好；
3. 98.9% 是**单次运行**；
4. **选择题只测「认出」**——我们另测过：同一系统选择题 83% 时开放式仅 19%；
5. 6 万字直喂成本低；**语料扩到 60 万字时方案不成立**（约 1000 元/次且可能超上下文）；
6. 灵枢库切块 900 字/块、千问 top-8 均未调参。
