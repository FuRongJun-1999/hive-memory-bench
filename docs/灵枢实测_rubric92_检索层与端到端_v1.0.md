## 1. 检索层（纯确定性，无模型）

```bash
HMB=<repo> python scripts/bench_state_track.py
# → {"n":552,"scope_infer_top1":0.9928,"oracle_judge_balanced":0.9801,
#    "tp":265,"tn":276,"fp":0,"fn":11}

HMB=<repo> python scripts/bench_scope_iter.py     # 五法 × 两条件
# 消融：lex 0.9601｜cooc 0.9928｜cooc_rare 0.9928｜cooc_margin 0.9928｜hybrid 0.9928
# 原query：lex 0.9221｜cooc 0.9928｜cooc_rare 0.9928｜cooc_margin 0.9891｜hybrid 0.9928

HMB=<repo> python scripts/bench_chapter_paths.py  # 四条检索路径
# 默认（全路）    原 1.000/1.000｜消融 0.9221/0.9964
# 仅 bm25        原 1.000/1.000｜消融 0.9112/0.9982
# bm25+entity    原 1.000/1.000｜消融 0.9112/0.9982
# lexical+bm25   原 1.000/1.000｜消融 0.9149/0.9982
```

**口径提示（避免混比）**：「词面」在这两个脚本里不是同一个东西——
- `bench_chapter_paths`（块级 11/12 行切块 + RRF 投票）消融 = 0.9221（这就是你表里的 92.21）；
- `bench_scope_iter` 的 `lex`（**整章 bigram 覆盖率**）消融 = **0.9601**、原 query = 0.9221。
两者都对，**但引用时必须写清是哪种词面**，否则会和共现的 0.9928 混成一锅。

## 3. 「标题泄漏」这条要更正归因

你说：消融只去掉「第N章」，stmt 里还留着「「生命的需求」」→ 标题相似度路径等于用答案。

**实测：消融后仍含「」的断言 = 0/552。** `strip_chapter` 的正则是
`第[一二三四五六七八九十\d]+章(「[^」]*」)?`，**连标题一起删**。

所以 100% 不是「消融后残留标题」造成的；它来自**原 query / 未消融**条件（章节号与标题本来就在 query 里，等于给了半个答案）。结论沿用你的判断——**100% 不可用、上限 99.28%**——但理由要改成「依赖原 query 的答案线索」，不是「消融没删干净」。
