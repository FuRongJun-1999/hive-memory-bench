# 压缩的代价就是因果丢失

> **一句话结论：抽取式/压缩式记忆系统交出的摘要，丢的不是"细节"，而是
> "与结论相矛盾的那一侧记载"——而因果推理恰恰要求同一事物上的两侧都在场。
> 信息压缩的代价就是因果丢失。**
>
> 本文是对「**为什么压缩式记忆系统得到的摘要内容无法完整推理因果关系**」的标准解答。
> 材料：本基准 23 章语料｜被测：六家（OpenViking／灵枢／朴素 BM25／Mem0／MemOS／Hindsight）＋ 直读对照
> ｜生成器：**全系统固定同一台**（`deepseek-flash`）｜题集：9 条人工裁定为「同一事物上的不一致」的结构性矛盾题
> （**题面与答案键未公开，本文只报读数**）｜成稿：2026-10-02

## 一 先给因果链（四步，每步都可机械复算）

```
① 压缩必然改写（逐字率：抽取式 18–45% vs 原文路线 100%）
        ↓
② 改写带走"词面" ⇒ 命题还在，句子不在（依据轴：引文可定位率 1.4–5.7% vs 100%）
        ↓
③ 而"矛盾的另一侧"本来就与题面词面不重叠（题面说 A，另一侧写的是"非 A 的另一种说法"）
   ⇒ 相似度检索按题面选段，系统性地选不到它（覆盖：0–5/9 vs 9/9）
        ↓
④ 于是因果推理只能架在"概括句"上：能说"有张力"，说不出"哪两处不能同时成立、依据在哪"
   ⇒ 证据链不可核实 ⇒ 无法完整推理因果
```

**关键在第③步**：这不是"压缩率太高导致信息不够"的直觉版，而是一个**方向性偏差**——
丢的不是随机信息，丢的是**与提问方向相反的那一侧**。

## 二 三条读数（同一批题、同一生成器，唯一变量＝检索出来的上下文）

### A 覆盖：「那一块」还在检索片段里吗（机械检查，不给模型看）

九条题各有一块**矛盾赖以成立的材料侧引文**（题面之外的另一侧）。检查它是否出现在该系统的
k=10 检索结果里（严格口径＝保留标点、逐字包含；括号内为宽松口径＝去标点、≥8 字公共块）：

| 系统 | 保住「那一块」的题数 |
|:--|--:|
| 朴素 BM25 | **9/9**（9/9） |
| OpenViking | 5/9（5/9） |
| 灵枢 | 5/9（5/9） |
| Hindsight | 1/9（1/9） |
| Mem0 | **0/9**（3/9） |
| MemOS | **0/9**（2/9） |

★ **律一：单句能保住，"对立对"保不住。** 当那一块只是**一句**（"记录说 X，材料里写着非 X"），
三到四家能带回它；当矛盾需要**两处不同章的记载同时进入同一个 k=10**（甲在某章说"反对权威"，
乙在另一章写"唯有强大的王者…才是自由的前提"），**除 BM25 外全军覆没**。
原因就是第③步：另一侧与题面**词面不重叠**，相似度排序天然把题面侧排在前面、把对面那一侧挤出 top-k。

★ **律二：压缩越狠，丢得越彻底。** Hindsight 1/9 ＜ MemOS 2/9 ＜ Mem0 3/9（宽松）
＜ 原文检索两家 5/9 ＜ 无筛选的 BM25 9/9——**单调**。

| 系统 | 材料 | 指出数 |

| 朴素 BM25 | 检索片段 | **6/9** |
| 直读（对照） | 全书 23 章 | 5/9 |
| OpenViking | 检索片段 | 5/9 |
| 灵枢 | 检索片段 | 5/9（允许同义替代依据时 6/9） |
| Mem0 | 检索片段 | 4/9 |
| MemOS | 检索片段 | 2/9 |
| Hindsight | 检索片段 | 1/9 |

★ **律三：「覆盖」与「指出」逐格对齐**——没带回那一块的系统，就是答不好的那一家；
而且**携带全部必需块的 BM25 反超了直读全书**（6 vs 5）：聚焦抵消了材料变少。
这条同时说明：**问题不在生成器的推理能力，在喂给它的上下文里"那一块"在不在**。

★ **律四：改写体的"推理"看上去成立，但无法核实。** 抽取式三家的引文是它们自己写下的概括句，
原文里不存在；而且它们**声索更多**（"补充证据"条数 10–14 条 vs 原文路线 2–3 条）——
**声索多、可核实低**。推理内容可能对，但因果推理要求"每一步可被外人核对"，
这一点上它们整条证据链不可核实；这不是调参能救的，是**改写**这一动作本身带来的。

## 三 结论：压缩的代价为什么恰好是因果

1. **因果推理的最小单位不是"事实"，是"同一事物上的两处记载"**（制度要求 vs 实际状态、
   同一概念的两个定义、意志 vs 人群需求…）。只有一侧时，任何"因为…所以…"都退化成**单侧叙述**。
2. **压缩把语言压成命题**。命题能表达"某事物是什么"，但**对立面的措辞**在改写中被拉平：
   原本"X"与"非 X 的另一种说法"之间的张力，被压成两条互不冲突的概括句。张力消失，因果也就没了落点。
3. **相似度检索进一步放大它**：检索按"与提问的相似度"排序，**提问指向哪一侧，哪一侧就被选出来**；
   而"对面那一侧"按定义就是与提问**不相似**的文本 ⇒ 系统性地缺席。压缩率越高（抽取越狠），
   词面保留越少，这个偏差越大——这就是 §二 A 的单调律。

**⇒ 因此：**
- 对**使用方**：要因果推理，就必须保证上下文里**同时**有同一事物的两侧记载——
  这不能靠"提高压缩质量"解决，只能靠**检索侧显式保留反面对立面**（或直接给原文）。
- 对**评测方**：只看"摘要是否正确"是不够的（摘要是对的），必须量
  **对立面在不在**（覆盖）＋**引文可不可核实**（依据轴）。本文的三条读数就是给这个用的。
- 对**压缩式系统**：可核实性（逐字回源）与因果完整性是两个不同的指标；
  前者可以靠"回源"补上，后者**必须**由检索侧负责把对立面带回来。

## 四 可操作：把这套检查跑在你自己的语料上

`systems/压缩代价.py`（纯标准库、无外部依赖）：

```bash
# 1) 准备：材料全文（一个或多个 .txt/.md）＋ 你的记忆系统对若干问题的检索结果
# 2) 准备：矛盾对清单 pairs.json —— 每对是"同一事物上的两处记载"的逐字引文
#    [{"a": "……", "b": "……"}, …]
python 压缩代价.py --material ./corpus --retrieval ./runs/my_system/retrieval \
                   --pairs pairs.json
```

它会给出三列：**两侧存活数**（检索有没有把对立面带回来）、**依据轴定位率**
（自家答卷引文能否在材料里逐字定位——若你的系统交的是改写体，这一列会很低）、
**每题明细**（哪一对只剩了一侧）。

## 五 边界（必须与读数一起读）

1. **材料量未对齐（原生口径）**：各家 k=10 实际给出的是 1.5k–27k 字符不等。
   本文问的是"**它检索出来的东西**丢不丢那一块"，即原生体验；材料量对齐后的读数见
   [`记忆系统对比_v1.0.md`](记忆系统对比_v1.0.md)（那里 BM25 与抽取式三家的差距会缩小，但**方向不变**）。
2. **BM25 是下界对照，不是推荐方案**：它无筛选地交原文，所以"覆盖"满分——代价是检索准度
   （见对比报告：地基句只碰 30–37%）。原文路线（OpenViking／灵枢）在**准度与保真**之间取舍，
   它们丢的那一半，正好是"对面那一侧"。
3. **本文只报机械层**：判官层（推理内容好坏）按多人判官协议另测，需要锚自证达标才可报值。
4. **题集未公开**：9 条矛盾题的题面、答案键、以及每条"那一块"的位置均为未公开题集，
   本文只报聚合读数；**上表可复算的只有口径与计数**，题目本身不随文发布。
