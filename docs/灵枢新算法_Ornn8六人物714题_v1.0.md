## 2. 跑法与踩坑

```bash
# 1) 逐人物增量作答（6 人物，共 845s）
python _ornn_answers.py --persona P01        # …P12/P14/P16/P17/P20
# 2) 生成判分包（714 题）
python grading/grade.py prepare --answers answers_all.jsonl --out packets.jsonl
# 3) 判分（judge-prompt + packet → reviews.jsonl）
python _ornn_judge.py
# 4) 记分
python grading/grade.py score --packets packets.jsonl --reviews reviews.jsonl --out judgments.jsonl --summary summary.json
```

**坑 1（会卡住 score）**：判分模型偶尔把 `required` 给出非严格布尔 / 缺位，`grade.py` 会直接 `ValueError: Invalid required decisions`。修法：按 `packets` 里 `rubric.required` 的长度强制对齐（缺位补 `false`、字符串转布尔、哈希从 packet 回填），再跑 score。
**坑 2**：判分要回填两个 SHA-256（answer/rubric），否则 score 拒收；模型常漏，必须由脚本补。
**坑 3**：`answers_all.jsonl` 里若有题缺答，score 只统计已判分题（分母会变小），务必核对 714/714。

## 3. 边界（这份数不能当什么用）

1. **不是灵枢原生 QA**：作答模型是 `deepseek-chat`，灵枢只提供记忆检索与选桶；换作答模型或换成本地模型，读数会变。
2. **判分模型不是 Codex**：作者用 Codex 判分，这里用 `deepseek-chat`（相对宽松/严格都未知）；不能与该榜单上 Codex 判的分数直接排名。
3. **本卷是 1.0 六人物卷**，不含 2.1 挑战赛（两榜、成本计分、网关计价）。
4. 单次运行；未做同条件重复测量。
5. `bucketindex` 每题重建是评测脚手架的做法，不代表线上灵枢的增量代价。

## 5. 时间类抽样复测（2026-11-10 晚，灵枢 #849 timeboost 分支）

按 Ornn8 answer-key.jsonl 的 content_tags 取并集：**相对日期 44 + 时间题 48 + 时间约定 43 → 去重 75 题**（人物分布 P01 8 / P12 4 / P14 11 / P16 8 / P17 28 / P20 16）。

| 条件 | 通过 | 通过率 | 相对基线 |
|---|---:|---:|---:|
| 714 全量基线（旧代码 #847、prompt 无「今天」、无逻辑时钟） | 47/75 | 62.7% | — |
| timeboost + prompt 加「今天」（无逻辑时钟） | 45/75 | 60.0% | −2.7 |
| timeboost + prompt 加「今天」+ 逻辑时钟 | 44/75 | 58.7% | −4.0 |
| **算法关**（MDCG_SCOPESEL_COOC=0、MDCG_SCOPE_SELECT=0）+ 同上 prompt/时钟 | **47/75** | **62.7%** | ±0.0 |

**A/B：算法开 44/75 vs 算法关 47/75（−4.0 点，6 翻正 / 9 回退）。** 而「算法关」相对基线是 7 翻正 / 7 回退 —— **这条链路的抖动本身就有 ±7 题量级**，3 题差异落在噪声里。**75 题样本上测不出 timeboost 增益。**

**三个回传给算法侧的口径问题**：

1. md_cg/scopeselect.py:190 用 time.time() 真实时钟解析相对日期（_tb.query_dates(query, time.time())）。评测合同要求把逻辑时间推进到每题 now，否则「三天前」按 2026-11-10 算而不是按题目的 2026-04-18 算 —— 任何外部复测脚本都会踩这个坑；建议 pick_scopes 接受可注入的 now。
2. 作答侧不会算日期：即使检索到正确时间桶，答案仍要把「三天前」换算成具体日；这条链路只给了【今天】一行。
3. 判分抖动与算法增益同量级：需要 ≥300 题或同题重复 2–3 次取稳定集，才能判 3–4 点级差异。

**边界**：75 题是子集，不外推 714；「算法关」用两个环境变量合并关闭，未逐一消融；判分仍 deepseek-chat（非 Codex）。

## 7. 材料带日期后重跑：算法增益方向翻转 → 75 题测不出

按上一节归因（材料缺每轮日期 → 相对日期无锚），把脚手架改成**材料里每条记忆与每轮对话都带日期**（`[YYYY-MM-DD]` 前缀），同一批 75 题再跑 **2 臂 × 2 次重复**：

| 材料 | 臂 | r1 | r2 | **稳定通过** | 抖动 |
|---|---|---:|---:|---:|---:|
| 无日期（上一轮） | 算法开 | 47 | 50 | 47 | 3 |
| 无日期（上一轮） | 算法关 | 46 | 46 | 44 | 4 |
| **带日期（本轮）** | **算法开** | 49 | 46 | **46** | 3 |
| **带日期（本轮）** | **算法关** | 50 | 52 | **50** | 2 |

### 读法（两条，都要说）

1. **加日期本身是有效的**：关臂 44 → 50（+6 题稳定集），开臂 47 → 46（−1）。两臂原始分都涨（关 46→50/52、开 47→49），说明「材料带时间戳」确实对作答有帮助——但**它帮的是作答侧，不是算法**；
2. **算法开/关的差异方向翻转**：无日期时开臂高 3 题（47 vs 44），带日期时关臂高 4 题（46 vs 50），开独占 0 / 关独占 4。**同一批题、同一协议，只换材料格式，结论就反了** —— 这说明 ±3–4 题量级的差异完全由生成/判分抖动决定，**不是算法的效果**。

### 由此更正上两节

- 第 6 节写的「#850 后 A/B 翻正 +4.0 点」**不能作为增益证据**：修时钟是**正确性修复**（相对日期不该按真实今天解析），但它对 75 题的分数影响测不出来；
- 第 5 节的「−4.0」同理，也是噪声。
- 关臂独占的 4 题里有两道相对日期题（`P12-NEW-009/d03`、`P14-CASE-added-relative/d03`）——**带日期后关臂也能答对**，说明这类题的门槛在「材料里有日期」，不在「选桶算法」。

### 结论

**在 75 题时间样本上，灵枢的 timeboost/共现算法既未证明有增益，也未证明有害。** 要判 3–4 点级差异需要：样本 ≥300 题、每臂 ≥3 次重复、并用「稳定集 + 符号检验」；同时材料带日期这条应作为**评测脚手架契约**固定下来（否则任何系统都会被系统性扣分）。

## 8. 修材料窗口后：开臂稳定集 47 → 52（+5），算法增益仍只有 +2

按 §7 的归因改两处：① 材料**按被选中的日桶整段取对话**（不再只取全局 top-8，避免把「要算日期的那一轮」挤掉）；② prompt 加锚点规则「算相对日期时以那条消息前面的日期为锚，不是今天」。同一批 75 题、2 臂 × 2 次重复：

| 材料口径 | 臂 | r1 | r2 | **稳定通过** | 抖动 |
|---|---|---:|---:|---:|---:|
| 无日期 | 开 | 47 | 50 | 47 | 3 |
| 无日期 | 关 | 46 | 46 | 44 | 4 |
| 带日期 | 开 | 49 | 46 | 46 | 3 |
| 带日期 | 关 | 50 | 52 | 50 | 2 |
| **桶整段 + 锚点规则** | **开** | 53 | 53 | **52** | 2 |
| **桶整段 + 锚点规则** | 关 | 56 | 50 | **50** | 6 |

### 三条读法

1. **材料修法是本轮唯一确定的收益**：开臂 47 → 46 → **52**（+5~6 题），且两次重复都是 53/75（稳定集 52、抖动 2）——比任何算法开关都稳；
2. **算法开/关仍是噪声级差异**：本轮开 52 vs 关 50（+2，开独占 2 / 关独占 0）。三次 A/B 的方向分别是 +3 / −4 / +2，**不出稳定符号**，75 题判不了；
3. 关臂抖动 6 题（56 vs 50）比开臂（2 题）大，说明**开桶选择反而让生成更稳**——这条只有样本量足够时才能验证。

### 结论

- 时间类题的瓶颈排序：**材料窗口（+5~6）> 日期格式（+2）> 算法开关（±2~4，噪声）**；
- 若要继续，优先做「材料覆盖度」的对照（例如桶内整段 vs 桶内 top-16），而不是继续调算法开关；
- 仍未解决：判分非 Codex、样本 75 题、单机单次环境。
