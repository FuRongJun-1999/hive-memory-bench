# 灵枢实测：三种口径的分层读数与统一尺度提案（v2.1）

> 被测版本：**dsh-memory 0.10.0**（灵枢）。换版本须重测，不同版本读数不可并列。

> 日期：2026-11-10 · 被测：灵枢（`dsh-memory / md_cg`），main 含 #844（范围选择）、#846（章节解析修复）、#847（共现打分进生产）
> 题库：`mcq/reasoning/题目_多跳六元素_rubric92_平衡掩码.json`（92 题 / 552 断言，3 真 3 假）
> 本报告的每个数都标了口径；**跨口径混谈是本领域最大的读数污染源**。

---

## 0. 一句话

灵枢有三种可测口径，读数分别是 **97.83%（检索层）/ 97.83%（判定层）/ 93.12%（端到端）**；
前两档不调模型，第三档才与其它系统同尺。**引用时必须写明是哪一档。**


---

## 0.1 术语（本仓统一口径）

题库里只有三个角色，此前把它们混称为「判官」是错的：

| 角色 | 干什么 | 本仓是谁 |
|---|---|---|
| **作答/判定者**（verdict producer） | 看材料，输出「是 / 否」 | 七臂里是 `deepseek-chat`；灵枢判定层是**系统自身的确定性核对** |
| **判分器**（grader） | 拿 verdict 与金标比，算 TPR/TNR/φ | **永远是机械比对 `pick == answer`，零模型** |
| **判官**（judge） | 开放式答案的语义打分 | **本项目已废弃**，不得再用于本表 |

⇒ 本报告此后一律用「**verdict 产出者**」；「评判词/换模型」指的是**作答侧**的配置，不是判分侧。

---

## 1. 口径 A：检索层（纯确定性，不调模型）

**问法**：给定断言原文，系统能否选中「所引章节」这个时间桶？

| 配置 | top-1 | top-k | 说明 |
|---|---:|---:|---|
| 生产模块 `scopeselect.pick_scopes`（k=1） | **97.83%** | — | #847 默认路径 |
| 生产模块（k=3） | — | **99.82%** | 三桶内命中 |
| 消融：去掉「第N章」 | 97.83% | 99.82% | **与上表同值 ⇒ 对章节字面零依赖** |
| bench 独立脚本 `bench_state_track.py`（整章节点） | 99.28% | — | 与生产差 1.45 点，原因见 §5 |

复现：

```bash
HMB=<hive-memory-bench> python scripts/bench_scope_prod.py     # 生产模块，97.83%
HMB=<hive-memory-bench> python scripts/bench_state_track.py    # 独立脚本，99.28%
```

---

> 口径 A/B 的 verdict 与判定**都由灵枢自身产出**（确定性规则），没有外部 LLM 参与；
> 因此它们与七臂表不可混比——可比的只有口径 C。

## 2. 口径 B：判定层（纯确定性，不调模型）

**问法**：在选中的时间桶里，六要素是否逐字齐全 → 判真/假。

| 指标 | 读数 |
|---|---:|
| 平衡准确率 | **0.9783**（tp266 / tn274 / fp2 / fn10） |
| 口径说明 | 判定用「槽位值是否在该桶原文里出现」的**确定性规则**，不涉及 LLM |

⚠️ 这一档**不属于**任何「外部 LLM 出 verdict」横比表。它证明的是「判定能力」，不是「端到端表现」。

---

## 3. 口径 C：端到端（灵枢当检索器 + 外部 LLM 出 verdict）

**问法**：系统自己检索 → 材料交给外部 LLM 产出 verdict → 机械判分。

### 3.1 统一作答口径（verdict 产出 = deepseek-chat · T=0 · 中性提示词 · 材料含「## 第N章」标题行）

| 材料来源 | 材料均值 | n | 平衡准确率 | φ |
|---|---:|---:|---:|---:|
| **灵枢生产检索 top-1**（本仓复测） | 2,670 字 | 552 | **0.9312** | 0.8642 |
| **灵枢生产检索 top-3**（本仓复测） | ~5,300 字 | 540 | **0.9426** | 0.8879 |
| oracle 所引章（复测会话） | 2,710 字 | 552 | 0.8659 | 0.7352 |

### 3.2 换作答模型为 deepseek-flash（同材料、同中性提示词）

| 材料 | 判词 | n | 平衡准确率 | φ |
|---|---|---:|---:|---:|
| 所引章 + 标题行 | 中性 | 549 | 0.9419 | 0.8854 |
| 所引章 + 标题行 | **显式六要素规则** | 551 | **0.9782** | 0.9564 |
| 所引章（**不含**标题行） | 显式六要素规则 | 544 | 0.9436 | 0.8897 |

### 3.3 大材料口径（早期 `timepack`，1 万字/题）

| 材料 | verdict 产出者 | 读数 | 备注 |
|---|---|---:|---|
| 1 万字（多章拼接） | deepseek-chat | 65.2% | **已作废**：章节解析 bug（缺第 18 章） |
| 1 万字（多章拼接，修 bug 后） | deepseek-flash | **88.22%** | 与上一行不可混谈 |

> **口径澄清（2026-11-10 复核后修正）**：上表两行相差 23 点，但这两行**同时变了三件事**——章节修复 + 作答提示词加严 + 换模型。
> 用**同提示词同模型**只变章节修复时，实测只涨 **+1.3 点**（0.6522 → 0.6649；deepseek-chat / 中性提示词 / 单断言）。
> ⇒ **章节修复本身不是 23 点的来源**。本报告 §4 里 0.9782 与 0.8822 的差（−9.6 点）才是「材料规模」的净效应，
> 因为那两行提示词相同（显式六要素规则）、模型相同（flash），可直接相减。

---

## 4. 口径之间的差，被拆成了四个可测因子

同一批 552 断言，只变一个因子：

| 因子 | 变换 | 读数变化 | 结论 |
|---|---|---|---|
| **作答提示词** | 中性 → 显式六要素规则 | 0.9419 → **0.9782** | **+3.6 点** |
| **作答模型** | deepseek-chat → deepseek-flash | 0.8659 → 0.9419 | **+7.6 点** |
| **材料标题行** | 不含 → 含「## 第N章」 | 0.9436 → 0.9782 | **+3.5 点**（六要素的「章节」槽要能核对） |
| **材料规模** | 2,670 字 → 10,006 字 | 0.9782 → 0.8822 | **−9.6 点**（多章拼接稀释可核对性） |

**合计解释 11.2 点的口径差**（判词 3.6 + 模型 7.6），且**与系统本身无关**。

---

## 5. 两个"看起来矛盾"的读数，各有一条解释

1. **oracle（0.8659）< 生产检索 top-1（0.9312）**：oracle 更应该高。
   差异只能来自判分方式——本仓用**批量判**（一次 6 条断言），复测会话用**单断言判**（一次 1 条）。
   单断言更严格，批量能借同题 3 真 3 假的结构校准。**这条尚未做单断面对照，如实标注为待对齐项。**
2. **生产 97.83% vs bench 脚本 99.28%**：bench 脚本把章切成 12 行块，**实体被切断**时子串匹配不到；
   生产按真实节点（不切块）建桶，实测 99.28%，与脚本一致。⇒ 差异来自切块，不是打分。

## 6. 统一尺度提案（建议全仓采用）

```
verdict 产出：deepseek-chat（固定作答模型，写进表头；判分器恒为机械比对）
温度/长度  ：T=0，max_tokens=16
作答提示词：中性（"请判断该陈述在材料下是否为真"），不提示六要素结构
材料       ：系统**自己检索**出来的原文，含「## 第N章」标题行
材料规模   ：随各系统自己的检索策略（不强行对齐字数，字数单列）
判分方式   ：**单断言**（一次一条），避免同题结构泄漏
重复次数   ：单次运行，注明
```

**在该尺上，灵枢的分数是：top-1 材料 0.9312 / top-3 材料 0.9426。**
（上述两数为**批量判**，按提案改为单断言后预计下降 5–7 点，待补测后更新。）

## 8. 边界（不冒充）

1. 单次运行，无重复测量；换作答模型 TPR 会漂 3–8 点。
2. 灵枢的检索层依赖 `_bucketskel.json`（桶文本骨架，主库 5.72 MB，重建 53 秒），**骨架按每节点 600 字 / 每桶 2 万字截断**，超大日桶只覆盖前段。
3. 判定层（0.9783）用字符串包含判六要素，接近题目构造口径，**不能当模型能力读数**。
4. 「生产 97.83%」是在 bench 语料（23 章 / 146 节点）上取得的；主库（84 日桶 / 640 会话桶）只验了延迟与可跑，**未做 gold 对照**。
