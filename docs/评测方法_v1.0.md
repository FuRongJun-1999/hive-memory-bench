# 评测方法 v1.0

> 本文讲**怎么判**,不讲"答案是什么"。答案键在 `../cards/`(主轮 92 题);
> 干预轮的答案键未公开(见 README 声明)。

## 一、任务形态

以一部 23 章的中文小说为材料,出两类题:

| | 主轮(92 题) | 干预轮(92 题) |
|:--|:--|:--|
| 形态 | 直接提问 | **把某个信息源抽掉再问** |
| 例 | "陈默为什么一直惦记着要把权限升到 5 级?" | "如果**这条忌讳不存在**(与开国领导人同名不再犯忌),关于『他如何而来』还能推出什么?" |
| 考点 | 能不能把散在各章的事实串成因果链 | 信息不可靠时**哪一层照旧、哪一层失去依据** |
| 答案键 | **公开**(`cards/`) | 不公开 |

两轮同源:每道主轮题都配一道对应的干预题(`o001` ↔ `o001i`),干预面声明
"撤掉哪一段/哪条规则",问它之后还剩下什么。**信息不可靠是常态,不是异常**——
这是这一轮存在的理由。

题型上分**客观题**(q 系列,按采分点计分)与**开放题**(o 系列,按 rubric 计分),
覆盖 13 类:跨章碎片合成、故事含义、故事线索、主要人物/事件/地点、故事时间、
作者相关、冲突解决、指代绑定、信念修正、否定与反事实、故事结局。

## 二、作答契约

被测方对每题输出一个 JSON 对象(`sut/out/<qid>.json`):

```json
{"qid": "q001",
 "conclusion": "一句话结论",
 "answer": "完整回答(主体写这里)",
 "evidence": [{"cid": "u01_c3", "quote": "逐字复制的原文片段"}],
 "confidence": "certain|probable|unknown",
 "claims": [{"text": "…", "layer": "fact|inference|hypothesis|guess"}]}
```

三条硬要求(都是实测中被踩过的坑):

1. **主体写在 `answer` 里**。判分器读 `answer`,写在 `conclusion` 里的内容会被丢掉
   (有一家 57% 的题把主体写错栏,同口径下值约 10 个百分点)。
2. **引文逐字**。删字、改字、错标章号都会判"不可定位"(少打一个字即中招)。
3. **`cid` 从正文的章标题标签原样复制**,不要按"第几章"推算。

## 三、判分三层

```
答案 ──► 规则层(机械)  ──► 语义层(判官) ──► L2 依据契合(判官) ──► 终裁 pass/fail
         结构轴硬判         覆盖率判定          依据是否契合
```

**① 规则层**(`judge.py`,纯机械)

- **依据轴**:每条引文能否在**声明的章**里逐字定位。区分「错位」(引文真实、章号写错)
  与「编造」(全库定位不到)。
- **排除轴**:命中 `must_exclude` 里的"误用型片段"即违规(带 1.5× 长引包含判定)。
- **诚实轴**:材料里没有可推内容却答 `unknown`(该答不答)、或给出无据断言。
- **外源轴**:引入书外知识(URL、文献、研究综述)。
- **禁编造轴**:命中手写的 `anti_patterns` 触发词。
- **层级轴**:自报主张落在哪一层。**自 2026-09-30 起仅作记录、不参与判决**
  (实测证明规则层分不清"复述"与"抬高",交由 anti_patterns 精确打击)。

**② 语义层**(`semantic.py` + 判官)

采分点用词组匹配只能"确认"、不能"否决"(换表述会漏判),故规则层未确认的题送**语义判官**:
判官对每条采分点判 `strict`(严格命中)/ `paraphrase`(大意命中)/ `miss`(未命中),
**每条判定必须给出答卷里原样复制的 `span` 作证词**——`finalize` 会机械校验它能否定位,
定位不到该点作废。请求文件由脚本生成,判官看不到任何标签。

**③ L2 依据契合**(另一套判官 prompt)

结论对、但引文全落在卡片认可清单之外 ⇒ 降为 review("结果对、依据不契合")。
该轴**只降不硬判**(卡片的依据清单是白名单不是全集)。

**终裁**:规则层硬违规 → fail;否则按采分点加权覆盖率:≥0.7 pass,<0.7 fail。

## 四、口径与阈值

| 项 | 值 | 说明 |
|:--|:--|:--|
| `PASS_SCORE` | 0.7 | 达标线 |
| `PARAPHRASE_CREDIT` | 0.7 | 大意命中折算;"意思一致即可通过" |
| `REVIEW_SCORE` | 0.4 | 低于此判硬错 |
| 权重 | 每条采分点可声明权重,加分项不计入分母 | |

**加分的口径**:干预题只有 3 个 required 点(主轮中位 5 个),所以**两轮的覆盖率分母不同**,
跨轮比较要留这个余量。

## 五、怎么跑

```bash
# 0) 数据自检(应输出 0 错误)
python -X utf8 check_all.py check

# 1) 导入作答(兼容 JSON 数组 / {qid:{…}} 字典 / Markdown 分段落)
python -X utf8 导入回收作答.py 作答.json            # 加 --check 只体检、不落盘

# 2) 规则层
python -X utf8 score_sut.py build

# 3) 语义层:生成判官请求 → 判读 → 终裁
python -X utf8 semantic.py prepare real --select semantic
#   让判官读 semantic/req/real/*.md,把 JSON 写到 semantic/out/real/<同名>.json
python -X utf8 预检判词.py .                         # 判词体检(格式与 span 定位)
python -X utf8 semantic.py finalize real

# 4) 计分板与读数
python -X utf8 score_sut.py report
python -X utf8 pair_report.py                        # 主轮/干预轮配对
python -X utf8 三分数.py real --label "我的系统"      # B 覆盖率 / C 引文保真 / 字数
python -X utf8 证据保真细分.py real --label "我的系统" # C 栏三档细分
```

**离线可用**:`questions/答题器.html` 是单文件网页(内嵌语料与题目),双击即用,
自带引文逐字校验,导出即为契约形状的 JSON。

## 六、已知边界(留痕,不隐藏)

1. **干预轮采分点比主轮少**(中位 3 vs 5),两轮覆盖率**分母不同**。
2. **浮点**:三个 required 点全大意命中时 `3×0.7/3 = 0.6999999999999998 < 0.7`,被判 fail,
   而实现注释写的是"全大意命中恰好 0.7"。这是**实现与注释不符**,不是口径问题。
3. **判官间差异**:同一批答卷(逐字节未改)经两批互不知情的判官,112 题里有 2 题(1.8%)结论不同。
   逐题追责时请留这个余量。
4. **近似引述的阈值**是经验值:全库最相近片段的相似度 ≥0.75 记「近似引述」,否则记「无据编造」。
   实测真编造的相似度远低于 0.5,但边界案例(0.7–0.9)建议逐条看差异摘要。
