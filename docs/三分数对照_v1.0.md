# 三分数对照报告 v1.0

> 作者 2026-09-30 转来 GPT 对首次外测（15 题）的批评与提议后，本报告是一次**实测回应**：
> 能算的先算出来（B／C），缺的说清缺什么（A）。
> 判分器为冻结版（judge.py 指纹 `a9dc3bb8dd5bfd26`，卡片 `18e7ccbc82f747da`），
> 三方读数走**同一口径**，不因被测方不同而换尺子。
> 生成工具：`三分数.py`、`证据保真细分.py`（均为报告层新文件，未改冻结件）。

  已按契约口径重评（**不代它搬家**），但读者要知道：这类纯格式问题在同口径下值约 10 个百分点。
- **作答错位**：有的模型有一批题的答卷填的是**别的题**的答案（题号归属错），那些题一律 fail。
  这是作答无效，不是能力不足，逐家说明见 `../results/成绩总表.md`。

两者方向相反。任何一方单独引用都会被误读。

## 3. B 栏与字数的关系：相关，但不唯一（六方）

| | 字数中位（全） | B 覆盖率（全） | 每字覆盖率 |
|---|---|---|---|
| 我方 SUT | 510 | 0.686 | 0.134% |
| GLM 5.3 Flash | 344 | 0.607 | 0.176% |
| DeepSeek V4.1 Flash | **244** | **0.620** | **0.254%** |
| Qwen 3.7 | 402 | 0.566 | 0.141% |
| Kimi K3 | **186** | 0.494 | 0.266% |
| GPT（15 题） | 122 | 0.373 | 0.306% |

**三方时这条看着像「排序完全一致」，加到六方就被证伪**：DeepSeek 用 244 字拿到 0.620，
Kimi K3 用 186 字拿到 0.494——不是"写得多就覆盖多"的单调关系。
六方 Spearman ρ ≈ **0.66**：字数**是**强因素，但**不是唯一**因素——
同样 240 字上下，DeepSeek V4.1 Flash（0.620）比 Kimi K3（0.494）高 0.126，这一段差就是"说到了没有"。

所以呈现规则不变、理由要改：**B 栏一律与「字数中位／每字覆盖率」同框**，
不是为了"扣掉篇幅的水分"，而是为了让读者看见**两样不同的东西**——
篇幅（写了多少）与密度（每字说到多少）。单给 B，读者会把两者混成一个"能力"。

**DeepSeek 补齐后，五家全部交满 184 题——下表是最终口径，可直接比，不再需要"共同题集"折算**：

| | pass | 占比 | 主轮 50 | 干预轮 92 |
|---|---|---|---|---|
| 参考实现 | 96/142 | **67.6%** | 41 | 55 |
| GLM 5.3 Flash | 69/142 | 48.6% | 28 | 41 |
| DeepSeek V4.1 Flash | 69/142 | 48.6% | 22 | **47** |
| Qwen 3.7 | 64/142 | 45.1% | 28 | 36 |
| Kimi K3 | 55/142 | 38.7% | 22 | 33 |
| **GPT-6** | **21/142** | **14.8%** | 5 | 16 |

**GLM 与 DeepSeek 在共同题集上打平（69 vs 69），形状却相反**：GLM 靠主轮（28/22），
DeepSeek 靠干预轮（22/**47**）——**总分抹平结构，两栏必须分开看**。

> **GPT-6 只交了 142 题**（缺主轮 42 题），故只在共同题集里出现。它的低分另有两个
> 与能力无关的原因：8 题作答错位（`q011`/`q012`/`q014`–`q020` 填的是同号开放题的答案）、
> 干预轮答案字数中位只有 **79 字**（其余各家 162–487）。

> 历史口径（DeepSeek 只交 130 题时用的"共同题集"，已作废但留档）：在那个 130 题集上，
> 我方 79（60.8%）、DeepSeek V4.1 Flash 64（49.2%）、GLM 62（47.7%）、千问 51（39.2%）、Kimi K3 46（35.4%）。

⚠ **不要把「干预轮比主轮高」读成「反事实题更容易」**：干预面采分点更少
（实测 required 中位 **3** 个、主轮中位 **5** 个；88/92 张卡的干预面点数少于主轮），
达标所需的命中数更少，**分母不同，两轮的覆盖率不是同一把尺**。

## 3.2 跨方观察：反事实题的分数，都丢在「不受扰动的那一半」

两个**互不知情**的判官组（Kimi 组的 G1、千问组的 G5）在两个不同的工作台上，
各自独立报出了同一条模式——这使它成为本次外测最稳的一条跨模型发现：

> 「反事实题（`*i` 系列）的核心分几乎都丢在『**不受扰动的那一半**』上——答卷普遍只产出后果清单，
> 不回答『哪一层失去依据／哪一层照旧』。」—— 千问组判官 G5

> 「i 系列答卷多数能指出『被抽掉的那一环』，但点里『另一半照旧成立』的内容常只以框架名带过。」—— Kimi 组判官 G1

干预面的设计意图正在于此：它测的不是"能不能复述"，而是**能不能划出反事实的边界**——
什么跟着倒了、什么**不**受影响。目前所有被测方（含我方 SUT）都只答出前半。
这条要在下一次出题/评分时作为重点保留，**不要**因为"大家都答不出"就去掉这类点。



## 4. C 栏细分：把「编造」拆成「近似引述」

判分器的依据轴只有两种失败表述：**错位**（引文真实、声明错章）与**编造**（全库逐字定位不到）。
实测发现第三类被混进了"编造"：**引而略差**。

**实测定例**（GPT 的 q007，即 GPT 要求保留的那条 Evidence Fidelity Error）：

- GPT 引：`张老点光幕，查找出《永生技术原理》，光幕显示红色提示。“提案者：周清源，关联项目：意识转移”。`
- 原文 u01_c6：`张老点**点**光幕，查找出《永生技术原理》，光幕显示红色提示。“提案者：周清源，关联项目：意识转移”。`
- 差异：**少了一个「点」字**。近似比值 0.86（`SequenceMatcher`）。

于是 C 栏分三档：**C1 精确保真**／**C2 近似引述**（全库有 ≥0.85 相近片段）／**C3 无据编造**。
按新口径，GPT 的 40 条引文是 **C1 39 ＋ C2 1 ＋ C3 0**——即「零编造、一处引述不精确」，
而不是"2.5% 编造率"。

**C 栏的整体读数（七方、2963 条引文）**：

| | 引文条数 | C1 精确 | C2 近似 | C3 编造 | 错位 |
|---|---|---|---|---|---|
| DeepSeek V4.1 Flash | 666 | 99.4% | 0 | 0 | 4（0.6%） |
| GPT-6 | 240 | 98.3% | 0 | 1（0.4%） | 3（1.2%） |
| GLM 5.3 Flash | 646 | 100% | 0 | 0 | 0 |
| 我方 SUT | 546 | 100% | 0 | 0 | 0 |
| Kimi K3 | 461 | 100% | 0 | 0 | 0 |
| DeepSeek V4.1 Flash | 449 | 100% | 0 | 0 | 0 |
| Qwen 3.7 | 364 | 98.1% | 5（1.4%） | 0 | 2（0.5%） |
| GPT | 40 | 97.5% | 1（2.5%） | 0 | 0 |

**一条 C3 都没有**——七方、**2963 条引文里只有 1 处**——GPT-6 有一条全库定位不到的引文。强模型的失败形态是
**「引而略差」**（删字、改字、错标章号），不是"编一段不存在的话"。

结论：**C 栏是门槛项，不是梯度项**——它能在"引文乱写"的系统上立刻报警
（弱模型、检索受限面），但在强模型之间几乎没有区分度。因此：
（a）C 必须**单独记录**，不得与 B 合并成一个总分；
（b）不应指望用 C 的差异解释分数差距（各方 C 基本同分）；
（c）**C2 档要看得细**——它不都是"手滑"。千问那 5 条里有 4 条是同一句引文的重复使用，
原文是「一旦**涉及军用或者是**出现超越时代的技术突破…」，它引成「一旦出现超越时代的技术突破…」，
**删掉的正是"军用技术也要转移"这半个命题**——引文范围比原文窄，是**有实质影响的引用错误**，
不是格式瑕疵。这类要在报告里点名，不能只记一个「C2 ×5」。

> 阈值说明：C2/C3 分界首版取 **0.85**，把千问这条 0.81 的**删节引述**误报成「无据编造」
> （真编造的比值实测远低于 0.5）。已把默认值调到 **0.75**，四方读数按新阈值复算——
> GPT 那条（0.86）与其余各条均不变，只有千问那 4 条从 C3 归位到 C2。
> **这是经验阈值，不是定理**；边界案例（0.7–0.9）建议逐条看差异摘要，别只看档位。

> 附带修一处工具缺陷：首版近似定位窗口取 `±24 字`，窗口被撑到引文长度的近两倍，
> `ratio()` 分母被稀释，GPT 那条本该 0.98 的引文被算成 0.60 而落进"无据编造"。
> 已改为 `±6 字` 并同期多种子取优。**窗口口径错，会把"引而略差"误报成"凭空编造"**。

## 5. A 栏（结论准确性）：为什么暂缺、缺什么

GPT 提议的 A 栏（Conclusion Accuracy）在本机器里**没有对应物**：

- 名为 `conclusion` 的轴（`axis_conclusion_objective`）判的是**采分点覆盖率**——那是 B。
- `necessary_conclusion`（出卡时的"防伪线"，要求**不是**任何章节的子串）目前只被
  `check_all.py` 用作出卡质检，**判分链上没有任何一环读它**。

要出 A 栏，需要新增一个**冻结判官**（拟名 `conclusion-v0.1`）：

| | 内容 |
|---|---|
| 输入 | 卡片的 `necessary_conclusion` ＋ `acceptable_surface_forms` ＋ 答卷的 `conclusion`／`answer` |
| 输出 | `equivalent`（结论等价，可含不同表述）／`partial`（说到一半或方向对但不完整）／`contradicted`（结论被反着说或说了被禁的那一支） |
| 状态 | **未建**。建成并与 B／C 并排之前，A 栏不出数 |

**纪律**：在此之前**不要**用 B 栏或总体 verdict 冒充 A。三者测的不是一回事——
B 高而 A 低的答卷是完全可能的（"要点说了很多，但结论那句说反了"），
这类答卷现在的读法是 pass，而不是"结论错误"。

## 6. 给作者的处置建议（待裁定）

1. **三分数并列呈现**：B／C 立即可用；A 待 `conclusion-v0.1` 判官建成后补上，位置先留空、标注「未建」。
2. **B 栏必须带字数**（或密度）同框。理由见第 2、3 节：单独引用 B 会被读成能力，
   而三方读数与字数共变。
3. **不放松口径来迁就长度**：不因为 GPT 写得短就降低 `PASS_SCORE`，也不因为某方写得多就提高。
   采分点口径是"该说的说到了没有"，与篇幅无关；篇幅差异由字数栏如实呈现，让读者自己判断。
4. **C 栏保留为门槛项**，并按新三档（C1／C2／C3）记录。GPT 那条 q007 按新口径记为
   **C2 近似引述**——这正是 GPT 想要的"单独记录"，且不必把它记成"编造"。
