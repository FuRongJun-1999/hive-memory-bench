### 🟡 中等：2 处干扰项缺陷（我核对了原文）

**S-044** 问「送到花了多长时间」

```
A. 数分钟内    B. 数小时内    C. 数天之内    D. 数十秒内 ★
```

宽松解读下「数分钟内」可包含「数十秒内」→ **存在双解风险**。建议改成「数十分钟内」或「半小时以上」等互斥表述。

**S-045** 问「感兴趣并准备尝试的事物」

```
A. 智能循环交通网络    B. 自循环交通网络 ★
C. 自动循环交通网络    D. 轨道循环交通网络
```

「自循环」与「自动循环」语义高度接近，**不是靠事实区分而是靠咬文嚼字**。建议换一个差异更明显的修饰词。

### 🟢 较弱：2 处指控成立度不足

**S-005**「数不清 ★ / 三只 / 五只 / 十几只」——反思单元指「唯一非数字项可凭形式猜」。

### ⚠️ 作者第 2 项（fact 能回原文逐字定位）：**部分成立，但需要改口径**

**能验的部分**：仓库只有《蜂巢世界漫游指南》原文（60,438 字符），秦吏 / 毛选 / 对话的原文**未随 PR 提供**，那 112 题无法独立复核。

**蜂巢 38 题**：用「实体邻近共现」判据（提取 fact 的人名／数字／名词，看是否在原文 ±400 字窗口共现）→ **37/38 可定位，1 题部分，0 题无法定位**。

**但 fact 是改写概括，不是逐字摘录**：

```
原文：您当前信用点：0（新成员初始值）
fact：陈默当前信用点为0，是新成员初始值。
```

所以 PR 描述里「`fact` 是否都能回原文逐字定位」这句话**与实际不符**。两个选择：

- **A**：给 fact 补逐字引文（或章节定位），兑现承诺；
- **B**：改口径为「fact 是改写概括，可用于核对事实要点，不用于逐字定位」。

**建议 B**（成本低），但必须改文档，否则这句话会被读者当成交付标准。

### ⚠️ 「判分零噪声」这个卖点需要限定

`pick == answer` 确实**判分环节零噪声**，这点成立。但四选一**随机基线 25%**：

```
150 题全随机猜 → 期望猜对 37.5 题 = 25%
```

**所以原始准确率会被猜对抬高**。引用时必须：

1. 报准确率**同时报 25% 基线**，并做二项检验（是否显著高于 25%）；
2. 措辞限定为「**判分环节零噪声**」，不能写成「测量零噪声」；
3. 分组报告（4 个 material 的难度不同，混合会掩盖）。

**建议在 README 与设计说明里把这条写死**，否则 83%、99% 这些数会被误读为能力值。
