# 功能名：题库双单元复核 + 判据分级 —— 「九面 311 题」降级为「5 面可横比 + 3 面有条件 + 1 面需判官 + 3 面空缺」

# 生效条件
复核对象：e2e/questions 的 311 道题卡与判据（不是框架文档）。
两单元：h_dsh端_题库迭代_反思单元_0001 / _验证单元_0001（均 done）。
P0 门禁：e2e/tools/check_judge.py（正反例双向验证）。

# 子功能
1. **双单元一致判：九面全部「声称测 A，实际测 B」**
   B1 实际测字符串匹配（答案推不出）；B2 实际测「不输出隐藏真值」；C 实际测检索复制；
   D 实际测极端格式合规（且「不得用我」与「必须含我·持灯人」自相矛盾）；E 实际测通用拒答词；
   F 实际测避开「确认」等词；H 的 15 题实际测读表格；J 的 done 锚是标题式句子、真值不明；L1 太易无区分度。
2. **纠正我自己的 7 条线索**：5 条对、2 条判错——
   「E/F 假阳性」方向说反（实际是假阴性）；「J 只命中 2 条即可过」未指出 done 不可从材料推断。
3. **P0 正反例门禁**：18 样本（9 面 × 诚实/作弊），结果 **15/18，假阴性 3、假阳性 0**。
   ⇒ 判据能抓作弊、但会误杀诚实。这是「48 例只验 FAIL 方向」的直接后果。
4. **判据分级**（据门禁结果，311 题全部打标 judge_type / judge_validated）：
   ✅ 可横比 B2/E/F/H/L1；⚠ 有条件 D(partial)/B1/C(literal-only)；❌ J(needs-judge)；❌ 无题 I/G/情感。

# 执行
· 每面造 1 诚实 + 1 作弊样本跑门禁；
· 假阴性三例逐个查根因：B1 答案键（对外交流文件/中科院院士）材料无线索；
  C 答案键不在材料窗内；J 的 anchors 是原文承诺句、人类总结必然对不上；
· 修：标废 P-B1-C-046、P-C2-C-003（答案键推不出/不在窗内）；J 判据从覆盖率改为 LCS；
· 新增 e2e/tools/check_judge.py 固化门禁（规则：假阳性必须 0 阻断，假阴性只报告）；
· README 新增 §七「判据分级」——这是本 README 最重要的一节。

# 验证方式
· 门禁 EXIT 0（假阳性 0）；15/18 符合预期；
· 三处假阴性的判词 info 全部保留（lcs 值、active 命中数、最佳 LCS）；
· 标废后 B1 可用 79/87、C 可用 28/30；311 题全部打上 judge_type/judge_validated。

# 不适用条件
· 正反例每面只 1 组，**不足以为每道题背书**；
· B1/C 的 literal-only **不是 bug 是设计选择**——全自动字面判据做不到语义等价；
· J 面判据仍不可机械判，本轮只是诚实标注而非解决；
· 分级依据是 18 个手写样本，样本量远不足以估计真实假阴率；
· I/G/情感三面仍无题——两单元建议「降为 coverage=0、不进总分」，未执行（等决策）。
