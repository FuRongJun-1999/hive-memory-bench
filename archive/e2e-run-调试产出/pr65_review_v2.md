### 🔴 五、新发现：`coverage_required: 0.7` 与选择题标准错位（系统性问题）

这是我这轮新查出来的，**影响面比 q007 大**。

`cards/*.yaml` 里**全部 55 张 open 卡**都有：

```yaml
grading:
  mode: rubric
  coverage_required: 0.7      ← 覆盖 70% 就算过
```

**但选择题判分是 `pick == answer`**——必须选中「完整」的那个选项。

**以 o027 为例**（你上轮点名的那题）：

| | 覆盖 | 论述题（70% 阈值）| 选择题 |
|---|---|---|---|
| A ★ | 5/5 = 100% | 过 | 对 |
| B | **4/5 = 80%** | **过（80% ≥ 70%）** | **错** |

**同一份答案，论述题判过、选择题判错。**

**这不是 o027 一题的问题**：任何「覆盖 70–99%」的选项都会遇到这个错位。你在 PR 里说「o027 的 B 漏一条要点但通顺，是否该判错」——**争议的根在这里**：不是 B 该不该错，是**两套标准不兼容**。

**三个解法**：

1. **改 rubric**：`coverage_required: 1.0`（论述题也变严，但口径统一）；
2. **选择题声明严格档**：明文写「选择题要求 100% 覆盖，与论述题 70% 阈值不同」，并在生成干扰项时只用「覆盖 <70%」的写法；
3. **改干扰项生成规则**：让「漏一条」的选项改为「漏两条以上」（覆盖 ≤60%），两边都判错。

**我倾向 2 或 3**——1 会让论述题历史读数全部作废。
