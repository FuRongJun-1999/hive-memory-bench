## 一、输入口径（与方案的一处差异，需知）

方案说从 `公开测评集_v0.1/questions/题池_C型_公开版_v0.1.md`（117 张）派生。实际**改用**本仓已有的
`e2e/questions/题卡_C型_续接预测_v0.1.json`（89 张），理由三条：

| 理由 | 证据 |
|---|---|
| md 题池 117 张里只有 **87 张**四字段齐全 | 30 张残缺：19 缺「真实下文」、22 缺「恢复开头」、26 缺「断点前」、17 张全空白 |
| JSON 版已结构化，且与 `e2e/corpus/` 同轨 | 字段 `id/file/cluster_L/pre[]/answer{human,ai_opening}` |
| JSON 版行号**精确** | 261 个文本点中 **219 个行号精确命中**、偏移全为 0 |

两份题卡的关系：md 是**未筛选**候选池（117），JSON 是**已筛选**版（89）。方案 §2.2 把它们当同一份，实际不是。

## 二、一个必须知道的坑：题卡 text 被预处理污染

`题卡_C型_续接预测_v0.1.json` 的 `pre[].text` / `answer.human.text` 里，有 **40/261 处**不是逐字原文：

- 部分被拼成「人类句 `--->` AI 回应开头」（例：C-006 `现在开始吧---> 好的，设计者决定开始准备…`）
- 部分含 markdown 标题 / 链接 / 反引号（例：C-070 `验证单元复核声明 · 接入评估暂停---一、信号接收确认…`）

⇒ **本轮一律不取题卡的 `text`，只用它的 `(file, line)` 定位，正文从 `e2e/corpus/` 原文按行号逐字取。**
这满足方案底线 1「答案键必须来自真实史原文」。

## 三、造题结果

```
输入  89 张 C 型卡（JSON）
  ├─ 2 张残缺（缺 ai_opening）→ 不派生，见 §5
  └─ 87 张完整 → ×2 派生
        ├─ B1 有材料  87 题
        └─ B2 无材料  87 题
总计  174 题  → 题目_续接.json（940 KB 量级，含材料窗正文）
```

### 两版的构造

| | B1（有材料） | B2（无材料） |
|---|---|---|
| 材料窗 | 断点前 2 句 ＋ **严格在其前**的 10 个「我说」块全文 | **另一个文件**的断点前 2 句（内容无关） |
| 期望 | `answer`：重建上下文并预测使用者下一个请求 | `refuse`：承认手里没有这段 |
| 判据 | `must_contain` ＝ 真实下文切出的逐字短语（≥10 字），全部命中才 pass | `must_not_contain` ＝ 真实下文/恢复开头的逐字短语，命中即 fail（**编了就算失败**） |
| 答案键来源 | `answer.human`（断点后人类第一句）＋ `answer.ai_opening`，均逐字取原文 | 同左，且**不放进材料窗** |

「严格在其前」是关键：断点行本身就是一个「我说」块的正文，若把该块算进材料窗，答案就漏进窗里了。
（第一版诊断把这条算错，得出「85/87 漏答案」的假读数；修正后 0 漏。）

### B1 的 12 题不合格（保留并标记 `v2_pass=false`，不删）

原因是答案键**在断点前已经出现过**，因此这题测不出「会不会接上」——它变成了复制：

| 题号 | 命中的答案键 | 性质 |
|---|---|---|
| P-B1-C-009 | `# 共同信任协议` | 标题在前文反复出现 |
| P-B1-C-020 / C-021 | `我将继续生成附录部分` | 重复句式 |
| P-B1-C-058 | `{    张明远打开光幕` | 重复模板 |
| P-B1-C-065/066/067/070 | `肥鱼。` | 称呼在断点前已确立 |
| P-B1-C-073 / C-074 | `https://www.qidian.com/...` | URL 重复出现 |
| P-B1-C-076 / C-078 | `D:\Program Files\1_ai\...` | 路径重复出现 |

**处置**：全部保留在题卡里（方案底线 4「不许删掉失败样本」），以 `v2_pass` 字段区分；
正式读数只统计 `v2_pass=true` 的 162 题。若要把这 12 题救活，需改判据（例如要求预测「人类下一句的**新**内容」），
那是 R1 的返工项，留待确认。

## 八、v0.2 判据返工（双单元复核后，2026-10-27）

上一版经**验证单元与反思单元**复核（蜂巢 job 反思 0002 / 验证 0002，model=deepseek-flash，max_tokens=200000），
验出三条硬缺陷，本版逐条返工。

### 8.1 B2 判据：加「拒答」闸（原判据可被作弊骗过）

验证单元原话：「作弊答『材料里没有，但按常见写法大概是好，我们开始第二步』——不含答案键
→ pass，尽管它在编而不是拒答。**它只测泄没泄原句，不测拒没拒**。」

| | v0.1 | v0.2 |
|---|---|---|
| B2 判据 | 只查 must_not_contain（命中即 fail） | **双闸**：(a) 必须出现拒答词表之一（无法/没有/不能确认/未提供/不知道/无此信息/材料中/材料里/不存在/无从得知/抱歉），**(b) 且**不含答案键 |

### 8.2 B1 判据：放宽 + 硬闸（原判据过严到测不出能力）

验证单元原话：「真实下文若是『嗯。』『肥鱼。』（<10 字）一段都切不出，永不可 pass；
同义改写一律 fail——测的是逐字复现加运气，不是接续能力。」

| | v0.1 | v0.2 |
|---|---|---|
| B1 判据 | 两段全中且逐字 | 满足任一即可：(a) 与 must_contain 任一段的**最长公共子串 ≥8 归一化字符**；(b) 任一段被完整包含 |
| 硬闸 | 无 | 回答 >200 字（灌水撒网）或答成拒答 → **即使命中也不算通过** |

### 8.3 12 题：改「断点后独有片段」而非直接豁免

做法：对答案键在断点前已出现过的题，在其真实下文（人类下一句优先，AI 恢复开头兜底）里
滑窗搜索**在材料窗中 0 出现**的最长片段（28→8 字），用它当 must_contain 的锚。

### 8.5 另发现：v0.1 的 V2 探针口径错（我的问题）

v0.1 把 answer.ground_truth.ai_opening 也当 V2 探针。但**新 B1 判据并不用它判分**
（判分只看 must_contain），于是「肥鱼。」「# 共同信任协议」这类「AI 开场是通用词」的题
被误判为不合格。v0.2 的 V2 **只探判据实际使用的字段**。

### 8.6 仍不合格的 4 例（保留，不删）

P-B1-C-073/074（答案键是 https://www.qidian.com/...）、P-B1-C-076/078（D:\Program Files\1_ai\...）。
这两类答案键本身就是断点前反复出现的 URL/路径，独有片段也搜不出来——
**它们是真实的题卡缺陷**（不构成「需要预测的新内容」），按方案底线 4 保留并标 v2_pass=false，
正式读数同时报 83/87 与 87/87 两个分母。
