# hive-memory-bench · 记忆系统选择题基准

各种记忆系统到底记住了什么、又忘了什么？这个项目把长文本里的事实、线索、因果和人格整理成**判断题与选择题**，用同一套规则比较不同系统。

**判分器零模型**：`是/否` 或 `pick == answer` 即通过，判分永远是机械比对，换谁复核读数都一样。

目前覆盖三类：**端到端简单检索**（150 题）、**复杂推理**（476 条 + 92 题）、**人格一致性**（108 / 180 题）。

## 交给 Codex 测试

把下面这段话发给 Codex，填上要测试的系统地址或本地路径：

```text
请使用 https://github.com/FuRongJun-1999/hive-memory-bench 测试这个记忆系统：[项目地址或本地路径]。
请先阅读仓库的判分说明和三类题库说明，再用 mcq/ 下的题目完成接入、作答和判分，
给我总成绩、分类成绩和测试配置。历史交给被测系统的记忆流程处理，
考试时不要把完整历史或标准答案直接交给作答模型。请保留实际回答与判分结果。
```

## 已经测过哪些

### 同尺表（口径 C：系统自己检索 → 外部 LLM 出判定 → 机械判分）

> **只在这张表里横比**。所有行的判定都由**外部 LLM**（`deepseek-chat`，T=0，中性提示词）产出，判分器均为机械比对。

| 系统 | 材料均值 | 平衡准确率 | φ |
|---|---:|---:|---:|
| **灵枢 top-3**（本仓复测）| ~5,300 字 | **0.9426** | 0.8879 |
| **灵枢 top-1**（本仓复测）| 2,670 字 | **0.9312** | 0.8642 |
| dsh-memu-memory（两跳·章节）| 5,379 字 | 0.8730 | 0.747 |
| 只给所引章节（参照基线）| 2,670 字 | 0.8659 | 0.7352 |
| dsh-memu-memory（两跳·块）| 2,061 字 | 0.8370 | — |
| surfcore 0.8.6 | 25,250 字 | 0.8210 | 0.748 |
| OpenViking 0.4.22 | 25,484 字 | 0.7660 | 0.642 |
| 千问 RAG | 9,727 字 | 0.6960 | 0.556 |

**两条可直接引用的**：

1. **材料多 ≠ 分数高**：surfcore 给了 25,250 字（灵枢的 9.5 倍），只得 0.8210；灵枢 2,670 字得 0.9312。
2. **命中之后还要答得对**：千问 RAG 与 OpenViking 的「所引章召回」有 97.1% / 90.4%，但端到端只有 ≈70% / ≈79% —— **瓶颈是材料纯度与定位，不是检索召回**。

详见 [三种口径与统一尺度 v2.0](docs/灵枢实测_三种口径与统一尺度_v2.0.md)、[插件实测 dsh-memu-memory](docs/插件实测_dsh-memu-memory_检索面_v1.0.md)、[千问RAG与OpenViking补测](docs/新推理库_千问RAG与OpenViking实测_v1.0.md)。

### 三种口径（以灵枢为例，**引用时必须写明是哪一档**）

| 口径 | 问什么 | 要不要调 LLM | 灵枢读数 |
|---|---|---|---:|
| **A 检索层** | 给定断言，能否选中「所引章节」这个时间桶 | 否（纯确定性）| top-1 **97.83%** / top-k 99.82% |
| **B 判定层** | 在桶里，六要素是否逐字齐全 | 否（纯确定性）| 平衡准确率 **97.83%** |

**跨口径混谈是本领域最大的读数污染源。** A、B 两档不含外部 LLM，**只能内部看**；能与其它系统横比的只有 C。

## 三类题库

| 类 | 题数 | 判分 | 测什么 |
|---|---:|---|---|
| [端到端简单检索](mcq/e2e-simple/) | 150 | `pick == answer` | 答案落在某一段内的单跳事实题 |
| [复杂推理](mcq/reasoning/) | **476 条 + 92 题**（552 断言）| `是/否` | 六元素 476 条 + 多跳 rubric_92（**均测记忆**）|
| [人格一致性](mcq/persona/) | 108 / 180 题 | 三级检验（T1/T2/T3）| 换说法、被攻击、被诱导时守不守得住人格 |

**三类不可互相替代**：简单检索测「找得到」，复杂推理测「串得起来」，人格一致性测「稳不稳」。

**为什么必须报闭卷**：原 238 题五选一开卷 100%，但**闭卷也能答对 82.8%**——不是记得，是选项本身泄漏答案。**只看开卷会把「选项语义自洽」误当成「记忆」。**

## 五分钟跑起来

只需 Python 3.10 或更新版本，无第三方依赖、无 API key、不产生模型费用。

```sh
git clone https://github.com/FuRongJun-1999/hive-memory-bench
cd hive-memory-bench

# 1. 系统读题（只给 stmt / question + options，不给 answer）
#    输出 sut/out/<qid>.json

# 2. 把 sut/out/*.json 汇总成 JSONL（每行 {"qid": "...", "pick": "B"}）
# 3. 判分：pick == answer 即通过
python grade_mcq.py --questions mcq/reasoning/题目_六元素判断题_476.json --answers answers.jsonl --out report.json
```

> `--answers` 需要 **JSONL 文件**，不是目录。

## 判分口径（引用读数前必读）

**0. 三种口径不可混谈** —— A 检索层 / B 判定层不含外部 LLM，只能内部看；与其它系统横比只能用 C 端到端。引用时写明是哪一档。

**1. 术语**（此前把三者混称为「判官」是错的）：

| 角色 | 干什么 | 本仓是谁 |
|---|---|---|
| **判定者**（verdict producer）| 看材料，输出「是/否」 | 同尺表里是外部 LLM；灵枢 A/B 档是自身的确定性核对 |
| **判分器**（grader）| 拿判定与金标比，算 TPR/TNR/φ | **永远是机械比对，零模型** |
| ~~判官~~（judge）| 开放式答案的语义打分 | **已废弃**，不得再用于本仓任何表 |

**2. 无泄漏硬指标**：入库前必须跑闭卷，**闭卷 − 随机 ≤ 10 点**才算达标。

**3. 闭卷 φ 报两个口径**：保守（没把握就答否）φ=0.000 / 激进（强制给答案）φ=0.348。**以保守报主读数，激进作泄漏上界**；横比须统一作答风格，否则「愿意猜」的系统虚高约 17 点。

**4. 格式非法率必须报**：作答输出不是 `A/B/C/D/E/?` 或 `true/false` 时会被判错，但那是**解析失败不是答错**。`grade_mcq.py` v2.3 起单独统计，>5% 打警告。

**5. 只测「认出」**：不测自由复述——同一系统选择题 83% 时，开放式仅 19%。

## 边界

1. **同尺表只覆盖 8 个臂**，且除灵枢外均为一次性初判；
2. **六元素 476 有 +8 点泄漏余量**（闭卷 58.0% vs 随机 50%，旧模型口径）——勉强达标不等于零泄漏；
3. **多跳的闭卷泄漏上界 φ=0.348**（强制猜口径），保守口径 φ=0.000，两值并列；
4. **判定者不同则不可比**：换作答模型一项就差 7.6 点、换提示词差 3.6 点；
5. 人格一致性面**尚未选择题化**（仍是三级检验量表），三类口径未完全统一；
6. **全部单次运行**，无重复测量、无显著性检验；
7. 闭卷读数依赖模型先验知识，**换模型需重测**。
