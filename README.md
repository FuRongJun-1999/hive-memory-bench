# hive-memory-bench · 记忆系统选择题基准

各种记忆系统到底记住了什么、又忘了什么？这个项目把长文本里的事实、线索、因果和人格整理成**选择题**，用同一套规则比较不同系统。

**判分零判官**：`pick == answer` 即通过，不经过任何模型或人工，换谁复核读数都一样。

目前覆盖三类：**端到端简单检索**（150 题）、**复杂推理**（238 题）、**人格一致性**（108/180 题）。


## 三类题库

| 类 | 题数 | 判分 | 测什么 |
|---|---:|---|---|
| [端到端简单检索](mcq/e2e-simple/) | 150 | `pick == answer` | 答案落在某一段内的单跳事实题 |
| [复杂推理](mcq/reasoning/) | 238 | `pick == answer` | 跨章线索、反事实干预、以及「原文没答案」的拒答题 |
| [人格一致性](mcq/persona/) | 108 / 180 | 三级检验（T1/T2/T3）| 换说法、被攻击、被诱导时守不守得住人格 |

**三类不可互相替代**：简单检索测「找得到」，复杂推理测「串得起来」，人格一致性测「稳不稳」。

## 五分钟跑起来

只需 Python 3.10 或更新版本，无第三方依赖、无 API key、不产生模型费用。

```sh
git clone https://github.com/FuRongJun-1999/hive-memory-bench
cd hive-memory-bench

# 1. 系统读题（只给 question + options，不给 answer）
#    输出 sut/out/<qid>.json：{"qid": "S-001", "pick": "B"}

# 2. 判分：pick == answer 即通过
python grade_mcq.py --questions mcq/reasoning/题目_选择题_238.json --answers sut/out/ --out report.json
```

## 判分口径（引用读数前必读）

1. **随机基线必须报**：五选一理论基线 **20%**；报读数时须同时报基线与样本量并做二项检验，只报准确率不成立。
2. **「零噪声」只指判分环节**：`pick == answer` 证明判分可复现，**不表示测量零噪声**（干扰项质量、覆盖范围仍有误差）。
3. **选择题是严格档**：必须选中最完整那一项，与论述题「覆盖 70% 即通过」不兼容。
4. **只测「认出」**：不测自由复述——同一系统选择题 83% 时，开放式仅 19%。

## 边界

1. 全部单跳或跨章线索，不覆盖多文档/事件库级推理；
2. 干扰项质量依赖人工复核——语义近似度无法机械判定；
3. 人格一致性面尚未选择题化，三类口径未完全统一；
4. 全部单次运行，无重复测量、无显著性检验；
5. 复杂推理题的干扰项未按 v2.1 规则（漏两条以上）重写。

## 历史存档

[`archive/`](archive/) 保存已作废的论述题体系（470 题题库、92 张 rubric、旧判分器、旧读数与分析文档）。

作废原因：论述题判分依赖判分器与语义判官，同一批答案三种判法差 **65 个百分点**（18% → 83%），读数不可复现。
