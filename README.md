# hive-memory-bench · 记忆系统选择题基准

各种记忆系统到底记住了什么、又忘了什么？这个项目把长文本里的事实、线索、因果和人格整理成**判断题与选择题**，用同一套规则比较不同系统。

**判分零判官**：`是/否` 或 `pick == answer` 即通过，不经过任何模型或人工，换谁复核读数都一样。

目前覆盖三类：**端到端简单检索**（150 题）、**复杂推理**（292 题）、**人格一致性**（108/180 题）。

## 交给 Codex 测试

```text
请使用 https://github.com/FuRongJun-1999/hive-memory-bench 测试这个记忆系统：[项目地址或本地路径]。
请先阅读仓库的判分说明和三类题库说明，再用 mcq/ 下的题目完成接入、作答和判分，
给我总成绩、分类成绩和测试配置。历史交给被测系统的记忆流程处理，
考试时不要把完整历史或标准答案直接交给作答模型。请保留实际回答与判分结果。
```

|---|---:|---|---:|---:|---:|---:|
| **六元素判断题** | 200 | **测记忆** | **58.0%** | 50% | **+8.0** | 87.5% |
| **多跳题（旧·自然语言要点）** | 92 | 测推理（已作废） | 69.6% | ~5% | +64.6 | 87.0% |
| **多跳六元素 rubric_92** | 92×6 | **测记忆（多跳）** | **50.0%（φ=0.000）** | 50% | **0.0** | 87.1%（φ=0.745） |

> **2026-11-09 复测（[报告](docs/多跳六元素rubric92_验证报告_v1.0.md)）**：上面的 rubric_92 行是新口径、
> 同一次运行测得的 —— 单断言作答 + 平衡准确率，闭卷 **50.0%**（φ=0.000，零泄漏）→ 开卷（只给所引章节）
> **87.1%**（φ=0.745），**记忆信号 +37.1 点**；整题全对 6/6 为 38/92 = 41.3%。
> 旧「多跳 92」用自然语言要点，闭卷 69.6% 远高于随机 → **判为泄漏，已被 rubric_92 取代**。
> 六元素 476 与旧读数（58.0% / 87.5%）产生于**换模型之前**，同口径复测为闭卷 50.0%（φ=0.000）/ 开卷·仅章 74.2%
> —— 引用旧数字时必须注明「旧模型口径」。

> **为什么必须报闭卷**：原 238 题五选一开卷 100%，但**闭卷也能答对 82.8%**——不是记得，是选项本身泄漏答案。
> 只看开卷会把「选项语义自洽」误当成「记忆」。

## 三类题库

| 类 | 题数 | 判分 | 测什么 |
|---|---:|---|---|
| [端到端简单检索](mcq/e2e-simple/) | 150 | `pick == answer` | 答案落在某一段内的单跳事实题 |
| [复杂推理](mcq/reasoning/) | **292** | `是/否` ＋ `pick == answer` | 六元素 200（记忆）+ 多跳 92（推理）|
| [人格一致性](mcq/persona/) | 108 / 180 | 三级检验（T1/T2/T3）| 换说法、被攻击、被诱导时守不守得住人格 |

**三类不可互相替代**：简单检索测「找得到」，复杂推理测「串得起来」，人格一致性测「稳不稳」。

## 五分钟跑起来

只需 Python 3.10 或更新版本，无第三方依赖、无 API key、不产生模型费用。

```sh
git clone https://github.com/FuRongJun-1999/hive-memory-bench
cd hive-memory-bench

# 1. 系统读题（只给 question + options / stmt，不给 answer）
#    输出 sut/out/<qid>.json：{"qid": "S-001", "pick": "B"}

# 2. 把 sut/out/*.json 汇总成 JSONL（每行 {"qid": "...", "pick": "B"}）
# 3. 判分：pick == answer 即通过
python grade_mcq.py --questions mcq/reasoning/题目_最终版_292.json --answers answers.jsonl --out report.json
```

> `--answers` 需要 **JSONL 文件**，不是目录。

## 判分口径（引用读数前必读）

1. **无泄漏硬指标**：任何题库入库前必须跑闭卷，**闭卷正确率 − 随机基线 ≤ 10 点**才算达标。
   - 六元素：58.0% − 50% = **+8.0** ✅；多跳：69.6% − 5% = **+64.6** ❌（故只报推理，不报记忆）
   - 原 238 题五选一：82.8% − 20% = **+62.8** ❌（已标为泄漏对照臂）
2. **随机基线必须报**：报读数时须同时报基线与样本量并做二项检验，只报准确率不成立。
3. **「零噪声」只指判分环节**：`pick == answer` 证明判分可复现，**不表示测量零噪声**。
4. **格式非法率必须报**：作答方输出不是 `A/B/C/D/E/?` 时会被判错，但那是**解析失败不是答错**。
   `grade_mcq.py` v2.3 起单独统计，>5% 会打警告。
5. **只测「认出」**：不测自由复述——同一系统选择题 83% 时，开放式仅 19%。

## 边界

1. **六元素仍有 +8 点泄漏余量**——勉强达标，不等于零泄漏；
2. **多跳读数必须分清是哪一版**：旧「自然语言要点」版测的是推理（闭卷 69.6% 泄漏），
   新的 **rubric_92（六元素 + 平衡掩码）**才是测记忆的多跳版；两版读数不可并列、不可互推；
3. 干扰项与要点的语义近似度**无法机械判定**，只能 LLM 盲审或人读；
4. 人格一致性面**尚未选择题化**（仍是三级检验量表），三类口径未完全统一；
5. 全部单次运行，无重复测量、无显著性检验；
6. 闭卷读数依赖模型先验知识，**换模型需重测**。
