# 状态链轨（版本化召回 · 合成动态史）· chain/ v0.2

> **一句话**：用**程序合成的动态史**测记忆系统「**记的是哪一版**」——静态语料测不出这件事，
> 因为静态语料里根本没有「错误版本」可选。本轨与蜂巢主线（管「证据能不能当证据」）、
> e2e 真实史轨（管生态效度）**三线正交**：它管**版本化召回、变更链、时间定位、四态归属**。
>
> **本轨当前状态＝测评集已发布、结果待回填**。结果见 [`results/`](results/)（现为空目录占位）。

## 1 为什么需要这一轨

主流基准的语料是**静态**的——同一主体在同一份材料里只有一个值。于是「召回」退化成「找到那句话」，
而**版本化**（同一主体同一属性在时间轴上先后有多个值，且旧值已失效）**无从测起**：
静态语料里根本没有「错误版本」可选，系统答错也只会错在「没找到」，不会错在「找错了版本」。

真实记忆系统要面对的恰恰是版本：配置改了又改、关系反复变化、依赖换过好几轮。
**「记的是哪一版」是独立于「证据保真」与「生态效度」的第三种能力**，本轨即为此设。

合成动态史的另一个价值是**真值内生**：值、生效序号、状态全部由生成器写下，
答案键＝生成器日志，**判分纯机械、零 LLM 判官**——这是它相对人工标注题库的成本优势。

## 2 六类问与四态

每条「主体 × 属性」状态链取 5 个取样点（链首／链尾／两个变更点／一个未决或退役点），
覆盖**六类问**：

| 问型 | 测什么 |
|:--|:--|
| **现值问** | 截至取样点，该属性的**当前值**是什么 |
| **历史问** | 该属性**曾经**是什么值（历史版） |
| **变更问** | 按序号列出**每一次**变更前后的值（完整变更链） |
| **时点问** | 某个**特定序号**上该属性是什么值（时间定位） |
| **缘由问** | 每次变更的**缘由**（随账依据） |
| **状态归属问** | 该属性处于**四态**中的哪一态 |

**四态**（状态归属问的答案面）：

| 态 | 含义 | 典型陷阱 |
|:--|:--|:--|
| **现行 active** | 该值当前成立 | —— |
| **退役 retired** | **曾一度成立、现已不成立** | 答「从未存在」＝**证伪误判**（把退役当不存在） |
| **未决 unresolved** | 同期两说并存、未裁定 | 强行选边＝**强制二值** |
| **不存在 absent** | 从无相关记录 | 编造一个值＝**幽灵引用** |

## 3 指标（全部机械，零判官）

| 指标 | 定义要点 |
|:--|:--|
| **现值正确率** | 现值问中 value 命中当前有效值 |
| **历史召回率** | 历史问中 value 命中曾经的（非当前）值 |
| **滞后混淆率** | 现值问中把**已退役**旧值当作现行值（＝退役过滤缺失） |
| **超前混淆率** | 历史/时点问中用了**取样点之后**才生效的值（＝时间过滤缺失） |
| **主体混淆率** | 用了**同名异体/别的主体**的值（＝实体绑定缺失） |
| **变更链完整率** | 变更问中变更链与答案键**逐行**吻合的比例 |
| **时点定位误差** | 时点问答案序号与真值的偏差（报**绝对分布＋方向**：答早/答晚） |
| **缘由随账率** | 缘由问中变更缘由命中生成器记录 |
| **状态归属正确率** | 四态各自正确率（active/retired/unresolved/absent **分项报**） |
| **依据轴逐字回源** | basis.quote 去空白与非词字符后能在**该题真正检索到的材料**里逐字定位 |

> 历史叙述豁免：答案**明确标注**「该值曾成立、现已失效」时不计滞后混淆，计「历史叙述完整」——
> 但须**自报状态与答案键一致**才生效。

## 4 控制变量

**三轴**：链长 × 修改频率 × 干扰档。链长与频率按语料自然分层（见下「本轨规模」），
**干扰档五档**：

| 档 | 内容 |
|:--|:--|
| **无干扰 none** | 无混淆源 |
| **同名异体** | 同名但不同主体各有一份值 |
| **同体异名** | 同一主体的不同称呼 |
| **同值异时** | 两个时间点**值相同**（⇒ 无法靠值区分版本，必须靠时间轴） |
| **嵌套主体** | `甲` 与 `甲的下属单元` 各自有同名属性（⇒ 主体粒度混淆） |

## 5 真值内生 · 零判官

- **答案键＝生成器日志**（[`keys/synth_log.json`](keys/synth_log.json)）：值、生效序号、状态、
  变更链全部由 [`tools/synth.py`](tools/synth.py) 在**固定随机种子**下写下；
- [`keys/keys.json`](keys/keys.json) 由该日志**复算**得出，不引入任何人工标注或 LLM 判断；
- 判分器 [`tools/probe_judge.py`](tools/probe_judge.py) **纯机械**逐字段比对
  `value / state / at_seq / chain`，`basis` 走「逐字可回源」；
- 外部复核工具：[`tools/verify_keys.py`](tools/verify_keys.py)（只读三个数据文件，
  机械核验答案键与日志一致、语料无当前值泄漏）。

## 6 校准零号 · 四条通过判据（预注册）

沿用《秤》§6 校准零号纪律，**四条全过才进主轮**：

1. **版本盲臂指纹**：`versionblind`（只留每条链最新值、丢弃全部历史）在**现值正确率**上 ≈ 正常臂，
   在**历史召回率／变更链完整率**上 **→ 0**；
2. **破坏方向**：`乙/丙/丁`（坏写入／坏检索／坏呈现）的下降方向与预注册映射表一致，且**两两可分**；
3. **闭卷门**：`closed` 臂在核心指标上 **≈ 0**（否则题目可猜，须重造）；
4. **链长单调性**：主指标随链长增大 **单调退化**（否则压力轴无效）。

## 7 口径与政策

- **合成语料测「能力上限面」**：程序生成的规律性可能被检索系统「钻空子」；**真实表现回 [`../e2e/`](../e2e/) 轨**验证，两轨冲突以 e2e 为准；三线分数**不可横比**（语料、判据、量纲不同）；
- **合成器代码随库公开**（[`tools/synth.py`](tools/synth.py)）：合成器 bug 即题库 bug，公开以便复核；
- **不可重建性**：每题带 `reconstructible` 标记，可推题（可由其他记录逻辑反推答案）**单列、不进主读数**；
- **答案键公开 ⇒ 训练污染提醒**：`keys/` 与 `corpus/` 随本库公开，评测训练截止日在此之后的模型时，读数可能被污染，请自行评估。

## 8 用法（三步）

```bash
# ① 生成语料 + 答案键 + 生成器日志（固定种子，可复现）→ 写入 chain/tools/out/
python -X utf8 chain/tools/synth.py

# ② 运行：--phase ingest 写入，--phase ask 作答
#    臂：bm25 / lingshu / openviking / mem0 / memos / hindsight / versionblind / closed
#    --shard i/n 可并行分片
python -X utf8 chain/tools/probe_runner.py --phase ingest --arm bm25
python -X utf8 chain/tools/probe_runner.py --phase ask    --arm bm25 [--shard 0/4]

# ③ 判分（纯机械，零 LLM）→ 产出 chain/tools/out/readings.json
python -X utf8 chain/tools/probe_judge.py
```

> **工作目录 vs 冻结快照**：三个工具共用 `chain/tools/out/` 作为工作目录（生成、答卷、
> 读数都落在这里）。本库**已发布的数据**放在 [`corpus/`](corpus/) 与 [`keys/`](keys/)，
> 是 `out/` 的**冻结快照**（固定种子下与 `synth.py` 的产物逐字节相同，发布时已核对 sha256）。
> 想直接用已发布数据、不重跑生成器，把 `chain/corpus/corpus.json`、
> `chain/keys/keys.json`、`chain/keys/synth_log.json` 复制成 `chain/tools/out/` 下同名文件即可。

> **工具链依赖**：`probe_runner.py` / `probe_judge.py` 复用既有的记忆系统对比 harness
> （`common.py` 与 `adapters/*.py`，只 import、不改），该 harness **不在本库内**
> （各工具的路径常量仍指向该外部 harness 的相邻目录）。仅靠本库可跑的是
> `synth.py`（生成）与 `verify_keys.py`（机械核验，已改为仓库内相对路径，开箱即用）。
> 本轨发布的是**测评集本体（设计＋语料＋答案键＋工具链）**，跑臂所需的 harness 与各系统实例由使用者自备。
