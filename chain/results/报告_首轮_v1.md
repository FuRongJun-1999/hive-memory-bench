## 一 探针测什么

静态语料测不出"记的是哪一版"：一个事实从头到尾只有一个值。本轨用**程序合成的动态史**（每次修改都记账）
来测**版本化召回**——六类问，各有自己的"片面必错"点：

| 问 | 形态 | 片面必错点 |
|:--|:--|:--|
| 现值 | 现在是什么状态？ | 答出任何旧值即错 |
| 历史 | 第 k 次修改前是什么状态？ | 答现值即错（时间错位） |
| 变更 | 改过几次、每次从什么改成什么？ | 漏掉中间版本即"片面" |
| 时点 | 什么时候从 X 变成 Y？ | 时间答错即版本错乱 |
| 缘由 | 为什么改？ | 状态对但缘由错＝记账不全 |
| **状态归属** | 现在**是否**如此（含已退役／未决／从未存在）？ | 把"已退役"说成"从未存在"＝证伪误判 |

四态＝**现行 / 退役 / 未决 / 不存在**。真值全部来自生成器日志，**零人工标注、零判官**。

## 四 四条读出来的

1. **没有任何系统挡住"旧值"**：滞后混淆率 bm25 **27.7%**／灵枢 **29.8%**／Hindsight **34.0%**——
   三家在现值问上都有约三成的回答用的是**真实存在但已失效**的版本。这正是"片面必错"的量化形态：
   召回了一个**不该存在于当前时间**的值，而不是"没召回"。
2. **BM25 在版本面上反而最强**（现值 0.660／历史 0.808／变更链 0.964／逐字 0.906）。
   与蜂巢/e2e 两线的"朴素基线常常不弱"同向：**无筛选原文检索在"哪一版"这个问题上不吃亏**。
3. **灵枢：四态最强（0.822）但逐字回源最低（0.176）**。它的强项是"知道有这回事、状态判得准"，
   弱项是"交不出逐字原文"——与《秤》里"检索面最强、依据面吃亏"的形状同源，但这里更极端。
   （e2e 轨上灵枢逐字回源为 0.91，此处 0.18——**两轨的语料形态与检索单位不同，不可直接横比**，见 §5-③。）
4. **Hindsight：现值与历史几乎为零（0.043／0.090），但变更链 0.768**。
   它能列出"改过哪几次"，却给不出**当前值**与**指定时点的值**——与《秤》里"抽取式改写让值失去身份"一致；
   但它的变更链成绩说明**更新序列本身**被记住了。这是一条值得追的分野。

## 五 caveats 与边界（如实）

1. **五臂完成，三臂未参测**：Mem0 答卷 157/625（不完整，已排除出主读数）；**OpenViking 与 MemOS 被工具链的隔离守卫拒绝**——
   守卫的理由是正当的：OV 的 workspace 是全进程共享单目录（chain 库会写进既有 OV 库），且适配器会杀掉占用 19333 的进程；
   MemOS 只改 user/cube，落在**同一 Neo4j 图库**（逻辑隔离，非物理隔离）。要跑需另起专用端口/workspace 或显式认下污染。
2. **主体混淆率全为 0.000**——干扰档（同名异体／同体异名／同值异时／嵌套主体）**没有咬到任何一家**。
   两种可能：语料干扰强度不足，或该指标不敏感。**这是本轮最需要追问的一条**，下一轮应先做干扰档的阳性对照。
3. **灵枢逐字回源 0.176 与 e2e 轨的 0.91 差异大**：两轨语料形态（合成动态史 vs 真实对话）、检索单位与材料装配都不同，
   **不可直接横比**；本轮数字只在本轨口径内成立。
4. **判据③（链长单调退化）已被独立复核指出可被"常数猜测器"蒙过**，本轮实测：bm25 与 Hindsight 都不满足单调非增、
   只有灵枢满足 ⇒ 该判据既非恒真、也不足以单独当效度门。**下一轮应改用"被测臂与版本盲臂的差值"作判据。**
5. **合成语料测的是能力上限面**：程序生成的修改史是"干净的频繁修改"，真实修改伴随闲聊、离题、情绪化表达。
   真实表现须回 [`../../e2e/`](../../e2e/) 轨验证；两轨冲突时以 e2e 为准。
6. **滞后混淆率的分母是"现值问"（62 题，剔除可推题后）**——样本量小，读作方向而非精确值。
7. **成本（实测，含一次估算更正）**：本轮的写入与作答 API 花费本身很小（判分为零 LLM），
   但**工作流侧的子代理开销是主要成本**——两轮工作流共约 2.0 亿 tokens（本机账本按会话归因，
   其中工具链实现子代理单次 1100 万 tokens 量级），DeepSeek 余额 **¥236.12 → ¥131.62，实际支出约 ¥104**。
   此前一处口头估计（¥14）系余额尚未结算时的读数，**以本节为准**。
   教训：工作流子代理的长上下文重复读取是这类任务的主要花费，与"跑被测系统"的成本不是一个量级。
